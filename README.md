# AI Skill Gap Radar

Учебный MVP веб-сервиса, который помогает сравнить текущие компетенции пользователя с требованиями целевой роли, увидеть главные дефициты навыков и получить персональный план развития. Репозиторий подготовлен так, чтобы проект можно было клонировать и запустить на Windows без устных пояснений.

## Образовательная цель

Проект демонстрирует полный путь создания двустороннего AI-продукта: ролевой вход, кабинет бизнеса, кабинет студента, связанный цикл «задача → отклик → выбор исполнителя», безопасную работу с серверным API OpenAI и подготовленную схему Supabase.

## Пользовательский сценарий

1. На странице входа пользователь выбирает роль заказчика или исполнителя.
2. Заказчик создаёт бизнес-задачу, указывает результат, бюджет, срок и нужные навыки.
3. Студент видит задачу в общей ленте и отправляет содержательный отклик.
4. Заказчик получает отклик и принимает исполнителя; задача переходит в работу.
5. **AI Skill Gap Radar** помогает студенту обновлять навыки и выбирать следующий проект по максимальному разрыву до цели.

Отличительная функция — не просто общий AI-совет, а наглядный радар дефицитов с приоритетом, целевым уровнем и конкретным действием для каждого навыка.

## Настройка `.env.local`

В корне проекта уже создан `.env.local`. Заполните значения после создания внешних сервисов:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
```

- `OPENAI_API_KEY` — секретный серверный ключ OpenAI.
- `OPENAI_MODEL` — идентификатор доступной вашему API-проекту модели.
- `NEXT_PUBLIC_SUPABASE_URL` — URL проекта Supabase.
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` — публичный anon/publishable key; безопасность данных обеспечивает RLS.
- `SUPABASE_SERVICE_ROLE_KEY` — привилегированный серверный ключ Supabase.

Переменные `OPENAI_API_KEY` и `SUPABASE_SERVICE_ROLE_KEY` разрешено читать только в Server Components, Server Actions или Route Handlers. Не добавляйте к ним префикс `NEXT_PUBLIC_`, не возвращайте их из API и не выводите в логи.

## Получение OpenAI API key

1. Войдите на [OpenAI Platform](https://platform.openai.com/).
2. Создайте или выберите API project и настройте биллинг/лимиты.
3. Откройте раздел API keys и создайте новый secret key.
4. Сразу сохраните его в `OPENAI_API_KEY` файла `.env.local`: повторно полный ключ обычно не показывается.
5. Укажите доступную модель в `OPENAI_MODEL`. Список зависит от проекта и его прав.

Ключ ChatGPT-подписки не создаётся автоматически: ChatGPT и API-биллинг — отдельные продукты.

## Создание Supabase и применение миграций

1. Создайте проект на [Supabase](https://supabase.com/dashboard).
2. В **Project Settings → API** скопируйте Project URL и публичный anon/publishable key в `.env.local`.
3. Секретный `service_role` key скопируйте в `SUPABASE_SERVICE_ROLE_KEY` и никогда не используйте в браузере.
4. Откройте **SQL Editor** и по порядку выполните `supabase/migrations/202609230001_initial_schema.sql`, затем `supabase/migrations/202609230002_marketplace.sql`.
5. Убедитесь, что таблицы `profiles`, `projects`, `applications`, `student_skills`, `assessments` и `skill_gaps` созданы, а RLS включён.

Для командного процесса можно установить Supabase CLI отдельно и применить миграции командой `supabase db push`, но CLI не требуется для проверки локального интерфейса и намеренно не устанавливается этим проектом.

## Демонстрационные данные

После миграции откройте Supabase SQL Editor, вставьте `supabase/seed.sql` и выполните запрос. Скрипт идемпотентен: его можно запускать повторно. Он создаёт отдельную таблицу `demo_skill_gaps` и не требует поддельных пользователей Auth.

## Локальный запуск без токенов

Оставьте все значения в `.env.local` пустыми и запустите:

```powershell
npm run dev
```

Интерфейс полностью доступен без OpenAI и Supabase. Сессия, задачи, отклики, решения заказчика и значения радара сохраняются в `localStorage` браузера. Поэтому можно войти заказчиком, создать задачу, выйти, войти студентом, откликнуться и снова проверить отклик со стороны заказчика.

## Проверка перед демонстрацией

```powershell
npm run check
npm run dev
```

Сценарий для жюри:

1. Войдите как заказчик и создайте новую задачу.
2. Выйдите, войдите как исполнитель и найдите созданную задачу в ленте.
3. Отправьте отклик и покажите его статус в разделе «Мои отклики».
4. В кабинете заказчика примите кандидата и покажите переход задачи в работу.
5. В кабинете исполнителя откройте Skill Gap Radar и измените уровень навыка.

## Безопасность токенов

- Никогда не коммитьте `.env.local` и не пересылайте его содержимое.
- Не вставляйте секреты в Client Components, скриншоты, issue, логи или ответы API.
- Для браузера используйте только `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` при включённом RLS.
- Перед каждым коммитом проверяйте staged-файлы через `git diff --cached` и запускайте поиск секретов.
- Если ключ попал в Git или публичный лог, одного удаления файла недостаточно: немедленно отзовите ключ, создайте новый и при необходимости очистите историю репозитория.
- Для production задавайте секреты в настройках хостинга, а не храните их в репозитории.

## Известные ограничения MVP

- локальный вход определяет роль и хранит сессию в браузере, но пароль пока не проверяется сервером;
- рабочие данные сохраняются в `localStorage`; для многопользовательского production-режима требуется подключить Supabase Auth и таблицы;
- OpenAI и Supabase подготовлены конфигурационно, но интеграционные Route Handlers ещё не реализованы;
- профиль целевой роли и критерии оценки пока не версионируются;
- нет административной панели, аналитики качества рекомендаций и полноценного e2e-тестирования;
- AI-рекомендации должны проверяться человеком и не являются гарантией трудоустройства.

Лицензия намеренно не добавлена: её следует выбрать отдельно перед публичным распространением.
